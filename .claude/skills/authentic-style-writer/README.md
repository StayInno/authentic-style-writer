# /authentic-style-writer

Аналізує текст на AI-подібні патерни, виставляє оцінку та переписує його в автентичному людському стилі.

---

## Встановлення

Скіл вже знаходиться в `.claude/skills/authentic-style-writer/` — Claude Code підхопить його автоматично при наступному запуску в цьому проєкті.

---

## Використання

### Базовий режим — тільки текст

Просто передайте текст як аргумент:

```
/authentic-style-writer Certainly! It's worth noting that there are several important factors to consider when approaching this problem. Furthermore, it is advisable to leverage a holistic framework...
```

Claude проаналізує текст, виставить оцінку AI-подібності та поверне переписану версію.

---

### Розширений режим — з вашими текстами

Якщо ви хочете, щоб текст переписали **у вашому конкретному стилі**, додайте приклади власних текстів через маркери:

```
/authentic-style-writer
===MY WRITING===
[вставте 3–10 своїх текстів тут, мінімум 2000 слів загалом — стандарт стилометрії 2,000–5,000]
===DRAFT===
[текст який потрібно переписати]
```

Claude спочатку побудує **Style Card** — карту ваших стійких стилістичних рис — і використає її під час переписування.

---

### Збереження стилю для повторного використання

Після побудови Style Card (Format B) скіл запитає, чи зберегти стиль під короткою назвою. Якщо так — отримуєте **Saved Style** артефакт із frontmatter (`name`, `created`, `samples_count`, `corpus_word_count`, стилометричні таргети) і повним Style Card + Style Brief.

**У Claude Code** скіл одразу записує файл у [styles/](styles/) і додає рядок у `INDEX.md`. Наступного разу можна викликати:

```
/authentic-style-writer
===USE STYLE=== formal-blog
===DRAFT===
[текст для переписування]
```

Скіл прочитає файл, пропустить LEARN_STYLE / STYLE_BRIEF і піде одразу в ANALYZE.

**У claude.ai (браузер)** запис у файл не доступний (sandbox ефемерний). Скіл видасть Saved Style артефакт як markdown-блок із інструкцією:
- скопіювати у **Project → Instructions** для постійного зберігання, або
- зберегти локально як `.md` файл

Повторне використання у claude.ai — через Format D:

```
===STYLE CARD===
[вставити збережений блок повністю — frontmatter + Style Card + Style Brief]
===DRAFT===
[текст]
```

**Поради щодо назв.** Slug автоматично нормалізується (lowercase, дефіси). Краще `formal-blog`, `client-acme`, `telegram-2024`, ніж `style1`, `temp`. Збереження під існуючим slug перезаписує старий файл (з попередженням про дату). Скіл **не зливає** корпуси автоматично — для оновлення стилю прогоніть Format B з повним набором семплів і збережіть під тим самим slug.

## Що повертає скіл

| Секція | Опис |
|--------|------|
| **Style Card** | JSON з рисами автора + таблиця доказів (count на ознаку, статистика пунктуації). Тільки в розширеному режимі. |
| **Style Brief** | Міст від картки до переписування: APPLY (правила), IMITATE (синтаксичні шаблони з корпусу, які переписка має скопіювати), CARRY FORWARD (структурні інваріанти), TARGET BURSTINESS, DO NOT INTRODUCE (заборонені патерни). |
| **Saved Style** | (Format B) Опційний артефакт — frontmatter + Style Card + Style Brief, готовий до повторного використання. У Claude Code пишеться у `styles/<slug>.md`; у claude.ai видається як копіювальний блок із інструкцією для Project Instructions. |
| **Analysis** | Оцінка AI-подібності 0–10 + таблиця знайдених патернів + список розбіжностей зі Style Card. |
| **Replacement Map** | Міст від аналізу до переписування: для кожного сигналу — конкретна заміна (бажано з лексикону автора). |
| **Rewritten Version** | Переписаний текст, що зобов'язаний виконати Replacement Map і Style Brief. |
| **Trace** | Перевірка перед оцінкою: чи реально застосовано кожне правило Style Brief, чи не зʼявились заборонені патерни. |
| **Refinement Log** | До 3 додаткових ітерацій рерайту після першої. На кожній — повторний аналіз AI-сигналів і ціле́ний мікро-рерайт залишкових. Лог із AI score + стилометричними метриками по кожній версії. Рання зупинка, якщо текст «чистий» або плато. |
| **Final Rewrite** | Версія з найнижчим AI-likeness score серед v1–v4 (tie-break — пізніша). Саме її оцінює Evaluation. |
| **Evaluation** | Чотири оцінки, обчислені з Trace + Refinement Log (а не на відчуття): зниження шаблонності / збереження сенсу / відповідність стилю / стилометричні метрики + перелік «галюцинованого стилю» (має бути порожнім). |

## Шкала оцінки AI-подібності

| Оцінка | Що означає |
|--------|-----------|
| 0–2 | Читається природно, мінімум шаблонних патернів |
| 3–4 | Кілька гладких або шаблонних місць, загалом нормально |
| 5–6 | Помітно assistant-like у кількох місцях |
| 7–8 | Сильно шаблонний, мало індивідуальності |
| 9–10 | Майже повністю AI-типове письмо |

## Які патерни виявляє скіл

- **hedge-cluster** — нагромадження застережень (`"it's worth noting that it may potentially..."`)
- **over-explanation** — переказ того, що читач вже знає
- **even-pacing** — всі речення однакової довжини, немає ритму
- **low-lexical-diversity** — звужений вокабуляр, ті ж content-words повторюються (метрики: TTR, Simpson's Diversity Index)
- **redundancy** — повтор того самого змісту різними словами в межах абзацу (на відміну від `low-lexical-diversity`, повтор не слів, а пропозицій)
- **abstract-filler** — розмиті фрази без конкретики (`"leverage synergies"`, `"holistic approach"`)
- **assistant-opener** — початок з `"Certainly!"`, `"Great question!"`, `"Of course!"`
- **comprehensiveness-creep** — охоплення всіх можливих кутів, хоча запит був конкретний
- **passive-excess** — надмірний пасивний стан, який приховує суб'єкта
- **pronoun-deficit** — повтор власних назв і конкретних іменників замість займенників (`"Marie went... Marie bought... Marie returned"` замість `"Marie went..., bought..., and returned"`)
- **transition-cliche** — `"Furthermore"`, `"Moreover"`, `"In conclusion"`, `"It is worth noting"`
- **symmetry-forced** — штучні паралельні списки там, де краще підійшла б проза
- **syntactic-repetition** — повтор тієї самої синтаксичної конструкції в кількох сусідніх реченнях без потреби (`"X provides Y. A enables B. P facilitates Q."`)
- **enthusiasm-flatten** — рівномірна позитивність без жодного критичного погляду

Детальний опис кожного патерну з прикладами — у [ai-signals.md](ai-signals.md).

## Чому це працює — наукова валідація

Підхід скілу (humanization-парафраз для обходу стилометричних детекторів) має пряме підтвердження в літературі:

- **Sadasivan et al. 2023, *Can AI-Generated Text be Reliably Detected?*** — парафраз-атаки знижують точність детекторів **з 97% до 57–80%**, руйнують watermarking, нейромережні детектори та zero-shot класифікатори. Це базовий аргумент про те, чому humanization взагалі працює.
- **Mindner, Schlippe & Schaaff 2023; Schaaff, Reinig & Schlippe 2024** — детектори дають F1 > 96% на сирому ChatGPT-тексті, але **тільки 78%** на парафразованому. Падіння в 18 пунктів — це benchmark очікуваного ефекту.
- **Alshammari 2025** (arXiv:2507.17944) — humanization-атака на DeepSeek-v3-генерований текст знизила точність детекторів: Copyleaks → 71%, QuillBot → 58%, **GPTZero → 52%** (тобто близько до випадкового підкидання монети). Перший емпіричний тест humanization саме на DeepSeek.
- **Opara 2024 (StyloAI)** — встановлює baseline F1 = 0.81 на бенчмарку AuTexTification (160k+ текстів, EN/ES, 6 моделей-генераторів). Скіл використовує цю цифру як орієнтир для secondary detection-resistance evaluation у Stage 4.
- **Petryshak & Rybchak 2025** (DOI [10.32782/tnv-tech.2025.2.15](https://doi.org/10.32782/tnv-tech.2025.2.15)) — Simpson's D і TTR — топ-1 і топ-2 ознаки для розрізнення Human / ChatGPT / DeepSeek на 30k-датасеті. Підстава для жорстких порогів TTR ±15% і Simpson's D ±20% у Stage 3.

### Зовнішній валідатор для точних чисел

Скіл рахує метрики (stdDev, TTR, Simpson's D) через LLM-обчислення, що достатньо для практичних рішень, але не претендує на лабораторну точність. Для зовнішньої перевірки рекомендується **StyloMetrix** (Okulska, Stetsenko et al. 2023, arXiv:2309.12810) — open-source бібліотека з підтримкою **української, польської, англійської, російської** мов і ~120 готових стилометричних векторів. Її можна підняти локально й прогнати оригінал + рерайт, щоб отримати незалежні числа.

## Поради

**Якість результату залежить від корпусу.** Стандарт стилометрії — 2,000–5,000 слів від одного автора (Patel et al. STYLL; Eder 2015). Менше 2,000 слів → скіл позначить корпус як обмежений, усі риси підуть в `occasional`, а оцінка Style match буде обмежена 7/10. 3–6 семплів зазвичай нормально, але вирішує загальна кількість слів `W`, а не кількість семплів. Тексти підбирайте в одному контексті (пост → пости, лист → листи).

**Burstiness вимірюється кількісно.** Sentence-length stdDev корпусу стає таргетом для переписки. Людський текст показує stdDev ≥ 5 слів, GPT-4 за замовчуванням 0.2–0.4. Якщо переписка не вписалась у ±1.5 від таргета — скіл повертається до Stage 3.

**Лексичне різноманіття — друга кількісна вісь.** TTR (Type-Token Ratio) і Simpson's Diversity Index обчислюються на content words (без stopwords). Петришак & Рибчак (2025, DOI [10.32782/tnv-tech.2025.2.15](https://doi.org/10.32782/tnv-tech.2025.2.15)) показали, що Simpson's D — топ-1 ознака для розрізнення AI vs human на 30k-семпловому датасеті (importance 0.309 у Gradient Boosting), TTR — топ-2. У Format B `corpus_ttr` і `corpus_simpsons_d` стають таргетами, рерайт має лягти в ±15% (TTR) і ±20% (Simpson's D); інакше — повернення до Stage 3. У Format A значення лише повідомляються — без baseline TTR сильно залежить від довжини тексту, тому жорсткого порогу немає.

**IMITATE, а не лише «не роби».** Видалення AI-сигналів змушує текст «відходити» від машинного стилю, але не гарантує «руху до» вашого стилю (Patel et al., STYLL, 2024). Скіл будує блок IMITATE з 4–8 синтаксичних шаблонів вашого корпусу (з прикладом), і переписка зобовʼязана використати щонайменше половину з них.

**Скіл не змінює зміст.** Якщо оцінка "Meaning preservation" нижча за 8, Claude явно попередить про це позначкою ⚠.

**Скіл не вигадує стиль.** Якщо в корпусі немає довгого тире чи буллетів, він не додасть їх у переписаному тексті. Якщо ваші пости завжди закінчуються закликом до дії — це фіксується як `structural_invariant` і обовʼязково переноситься в переписку.

**Ітеративний рефайнмент.** Після першого рерайту (v1) скіл повторно аналізує отриманий текст на AI-сигнали та робить до 3 додаткових цілених проходів (v2, v3, v4). Кожна ітерація — мікро-Replacement Map тільки для залишкових сигналів. Рання зупинка, якщо AI score ≤ 2/10 і сигналів немає, або якщо набір сигналів повторюється (плато). Фінальною віддається версія з найнижчим AI score. Якщо рефайнмент не покращив v1 — повертається v1 з поміткою.

**Style match < 7** — скіл сам попередить і запропонує переписати ще раз із суворішим дотриманням Style Brief.

**Для сильного переписування** уточніть це в запиті:
```
/authentic-style-writer Rewrite aggressively, strong style change is OK.
[текст]
```
